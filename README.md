# 方向尋找

純 Kotlin 原生 Android 客戶端。沒有伺服器、沒有帳號。兩部手機都安裝這個 App，並授予藍牙與測距權限後，尋找中的裝置會在 **10 米**範圍內，即時畫出其他客戶端的方向。

公開倉庫：<https://github.com/wusui1325-dotcom/android-find-with-orientation>

目前版本：**1.2.0**（versionCode 3）

## 它做什麼

- 只用藍牙低功耗廣播一個私有服務 UUID，所以雷達上只會出現裝了本客戶端的裝置。
- 尋找端連接對端 GATT，交換名稱與 UWB 測距參數。
- 兩部都有 UWB 時，用 AndroidX `core-uwb` 做雙向測距。距離是米，方位角是相對手機頂端的角度，範圍約 -90° 到 90°。
- 沒有 UWB 時，用 RSSI 估算距離；使用者緩慢轉身後，取訊號最強的朝向當作大約方向。
- 室外、誤差夠小時，可用系統融合定位（`LocationManager` 的 GPS／網絡位置，經藍牙交給對端）作為後備，並標上誤差。室內衛星定位並不可靠。
- 估計或測距超過 10 米的裝置不畫上雷達。
- 可從尋找端向已連線的對端發出「呼叫」：對端會響鈴並震動，可在對端停止，並在短時間後自動結束。
- 可在設定中更改本機顯示名稱；名稱會經 GATT 與廣播同步給對方。
- 尋找進行中會保持螢幕常亮。可選「指向目標時震動提示」（預設關閉）。

## 硬體限制

實時角度不是每支手機都做得到。

| 能力 | 條件 |
| --- | --- |
| 實時方位角與距離 | 雙方都有 UWB，例如 Pixel 6 Pro 及之後的 Pro、部分 Galaxy S21+ 以後機型，且系統已開 UWB |
| 融合定位方向 | 室外、雙方誤差小於 30 米時可用；室內不要指望它 |
| 大約方向 | 無 UWB 時要緩慢轉一圈，讓程式對到訊號峰值 |
| 只顯示距離環 | 還沒轉夠，或角度尚未鎖定 |

單一天線藍牙不能像 UWB 那樣直接給出到達角。這不是雲端定位。本機設定裡的「本機能力」會列出 Wi-Fi RTT、藍牙通道探測、紅外與超聲波等硬體是否存在，但本版不會假裝它們已用於測距。

## 權限

藍牙掃描、廣播、連接、精確位置、粗略位置、UWB 測距（若此機有 UWB）、通知、震動。精確位置是因為部分系統在沒有位置權限時不回傳藍牙掃描結果。資料只留在兩部手機之間，不上網。App 沒有 `INTERNET` 權限。

## 使用

1. 兩邊都安裝「方向尋找」，並授予權限。
2. 按「開始尋找」，並打開「可被發現」。手機頂端對準前方。
3. 10 米內的對方會出現在雷達上。琥珀色是 UWB，綠色是融合定位，藍色是旋轉估計。
4. 點選對端後可按「呼叫對方」，讓對方的手機響鈴並震動。
5. 若希望關著畫面也能被找到，打開「常駐被發現」，並按「允許背景運行」。

## 常駐被發現

打開「常駐被發現」後，前景服務會一直廣播。開機或更新 App 後會自行恢復。常駐時只廣播、不掃描，等別的客戶端來找。尋找進行中會改用較積極的廣播與掃描；只被發現時會降低工作週期，以節省電量。

這不是強制停止後也能活。Android 不允許被強制停止的 App 自行起來。部分廠商還會殺前景服務，所以要再按「允許背景運行」。通知必須留著。

## 後備定位

優先順序是 UWB、融合定位、旋轉估計。

融合定位用系統 `LocationManager` 的 GPS 與網絡位置，經藍牙交給對端，再算方位角和距離。這是每支手機都有的方案，不依賴 Google Play。室外、雙方誤差小於 30 米時可用。10 米內的衛星誤差常常大於兩機距離，所以它標成綠色，並顯示誤差。室內不要指望它。

## 建置

可以拉下來直接編。需要 Android Studio、JDK 17、Android SDK 36。第一次同步會下載 Gradle 8.11.1。

```bash
git clone https://github.com/wusui1325-dotcom/android-find-with-orientation.git
cd android-find-with-orientation
./gradlew :app:testDebugUnitTest :app:assembleRelease
```

Release 建置已開啟 R8 縮減與資源壓縮。
